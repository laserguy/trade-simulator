Trade Simulator

How the AI agents in Trade Simulator work

Trade Simulator is a practice trading app. It manages a pretend portfolio of US stocks with virtual money, so no real money is ever at risk. Two AI agents research the market and decide what to buy and sell. The app's own code checks every decision before anything happens.

The AI decides The app's own code does it, with fixed rules
The cast

Two agents, each with two jobs

Trading Agent

  • Trading run: decides what to buy, sell or hold.
  • Strategy review: writes its own investment strategy, and judges it every week.

Research Agent

  • Research request: looks up prices, news and web articles when the Trading Agent asks.
  • Watchlist refresh: picks the short list of stocks the Trading Agent is allowed to buy.
1 · How the two agents think

Both agents think in a loop of turns

The Trading Agent and the Research Agent work the same way. A is one call to the AI model. Each turn the model reads everything so far, then does one of two things: asks the code to run , or gives its final answer. Tool results are added to the conversation, so every turn sees more than the one before.

Every job has a limit on how many turns it may take; section 2 shows them. Each turn sends the whole growing conversation again, so later turns cost more than early ones.

      2 · What each agent is made of

      Inside the Trading Agent and the Research Agent

      The Trading Agent and the Research Agent are built from the same parts: a goal, a model, a memory, a loop, tools and an output. What differs is how each part is set for each of their four jobs. One thing surprises most people: neither agent remembers anything between runs. Each run starts fresh, and the app's code rebuilds the agent's memory from saved data and writes it into the starting text.

      Trading Agent

      Started by
      Run now, or the schedule chosen in Settings: daily at market open, or every 15 minutes. The market must be open.
      Goal
      Beat the S&P 500 () over time. Holding cash is a decision too.
      Model
      Chosen in Settings. Same model for both agents, read fresh at the start of every run.
      Memory
      Written by code into the starting text:
      • cash, total value, holdings
      • why each stock still held was bought
      • current strategy
      • with reasons
      • latest
      • performance vs. SPY
      • this run's research budget
      Does not see: past runs, stocks already sold, its own earlier thinking.
      Loop
      Up to 10 turns.
      Tools
      Ask the Research Agent, at most 3 times per run. Optional tools: none set up.
      Output
      Orders, each with a reason and the strategy section it follows, plus a summary. In a .
      Then code
      Checks every order: buys must be on the watchlist · a price must exist · enough cash for trade + $1 fee · can't sell shares not held · a buy can't take one stock above 20% of the portfolio. Sells run first. Passing orders execute; the rest are rejected with a reason. The run is saved.
      Started by
      The Review button; the weekly schedule (15 min after the week's last close); or automatically before a trading run when no strategy exists. Reviewing needs at least 10 trading days and 5 completed runs on the current strategy. The first strategy can be written any time.
      Goal
      Same goal. This time it writes or reviews its own strategy instead of trading.
      Model
      Same model as trading runs.
      Memory
      The richest of all four jobs:
      • portfolio, watchlist, market overview
      • current strategy
      • a computed by code
      • every order in the period, with its reason
      • earlier strategy versions and why they were kept or changed
      First strategy: no scorecard or history yet.
      Loop
      Up to 2 turns: one answer.
      Tools
      None. No research, no MCP.
      Output
      Keep or change, with reasons; were targets met; was the strategy followed; the new strategy text.
      Then code
      Checks the answer is complete. If the strategy changed, saves it as a new version. Trading runs follow it from then on.

      Research Agent

      Started by
      The Trading Agent asking, inside one of its turns.
      Goal
      Research stocks and report facts with sources. It never decides trades.
      Model
      Same model as the Trading Agent.
      Memory
      Only the request text, plus a note listing current holdings and why each was bought. Sees nothing else from the Trading Agent.
      Loop
      Up to 12 turns, each time it is asked.
      Tools
      • quotes (up to 25 stocks per call)
      • company news (1–30 days back)
      • market news
      • key metrics
      • web search: 5 per trading run, shared across all requests
      Only web search is limited. Optional MCP: none set up.
      Output
      A research report: findings with sources, in a fixed format.
      Then code
      Keeps only source links the tools really returned, and attaches each stock's price and day change.
      Started by
      The Refresh watchlist button, any time, even with the market closed. Also runs once automatically when there is no watchlist yet and an AI key is saved.
      Goal
      Its research instructions plus extra refresh instructions: pick stocks from the and write the market overview.
      Model
      Same model.
      Memory
      Today's date, the current watchlist with reasons, the list of S&P 500 symbols, the search budget.
      Loop
      Up to 40 turns.
      Tools
      The same five tools; web search up to 20.
      Output
      Stock picks with reasons, plus the market overview that later trading runs read.
      Then code
      Drops picks outside the S&P 500, duplicates, and anything past 20 stocks. If nothing valid is left, the old watchlist stays.

      Turn limits, one per job

      10Trading run: the Trading Agent's turns in one run
      12Research request: the Research Agent's turns each time it is asked
      40Watchlist refresh: high, because it makes many free tool calls
      2Strategy review: no tools, just one answer

      These are safety ceilings, not targets. A normal run ends well before them. They stop a confused model from looping forever. If a job hits its limit, that job fails. The real limits on research are separate: 3 research requests and 5 web searches per trading run.

      3 · How the jobs feed each other

      Over days and weeks

      No job talks to another directly, except the Trading Agent asking for research. Everything else passes through saved data: one job saves its result, and the code puts it into the next job's starting text. Only one job runs at a time.
