# Trade Simulator: Problem Statement

> Living document. Updated whenever a decision is made or changed.
> The reasoning behind each decision is in [WHY.md](WHY.md) under the same decision ID.

## Summary
A **local, single-user paper-trading web app**. An AI **Trading Agent**, helped by one **Research Agent**, trades US stocks with virtual money and shows the reasoning behind every decision.

## Decisions (v1)

| ID | Topic | Decision |
|----|-------|----------|
| D1 | Scope | One exchange, one Trading Agent plus one Research Agent, virtual money only, no login. |
| D2 | Exchange | US (NYSE/NASDAQ). |
| D3 | Run mode | A toggle in the app: **Manual** (default), **Daily** at market open, or **Every 15 minutes** during market hours. "Run now" is available in every mode while the market is open (D21). The mode is chosen on the Settings page (D35). |
| D4 | Watchlist | The agent researches and picks **10–20 tickers from the S&P 500**. It trades only these stocks. The list is rebuilt **only when the user clicks "Refresh watchlist"**, with one exception: the **first watchlist is built automatically** as soon as there is no watchlist and an AI key exists (at start-up if a key is saved, or right after the first key is saved in Settings). This automatic build happens **once**; if it fails, the user retries with the button. The S&P 500 list comes from the open dataset `github.com/datasets/s-and-p-500-companies`. Picks outside it, or beyond 20, are dropped with a warning. If no valid picks remain, the old watchlist is kept. |
| D5 | Capital | Fixed **$10,000** of virtual money, stored in the exchange profile (D24) so other exchanges can use their own currency. |
| D6 | Trading rules | Whole shares only, a simulated **broker fee of $1 per trade** (buy or sell; set in the exchange profile, D24), at most **20% of the portfolio** in one stock, and **no shorting**. These rules are enforced in code, and the agent cannot override them. Details: the 20% cap is checked after the buy, against total portfolio value (cash + holdings at current prices); buys are allowed only for watchlist stocks, while any held stock can be sold; within a run, sells are processed before buys; cash can never go negative. |
| D7 | Data | Free-tier US market data (about **15 minutes delayed**) plus web search for news. Provider: **Finnhub free tier** (60 calls/min: quotes, company news, fundamentals), called directly through small agent tools rather than MCP. Market data sits behind an app-owned interface, with the provider chosen by `MARKET_DATA_PROVIDER` (default `finnhub`; D38). Finnhub's free plan has no price history; charts use D36. |
| D8 | Tech | A **Python** backend using the **OpenAI Agents SDK**, and a simple web UI on localhost. |
| D9 | Model settings | A **Settings page** where the user enters API keys for **OpenAI and/or Anthropic** and picks **one model used by both agents** (v1 scope; agent-specific models are planned for later, and the code keeps the model choice per agent internally so this can be added without reworking the agents). **Only models from providers with a key are offered**, each shown with its **price** (per million tokens), from a dated model catalogue in the app. Anthropic models run through the OpenAI Agents SDK's LiteLLM extension. Keys are stored locally only. Default model: **`gpt-6-luna`** (cheapest current OpenAI model). LLM keys come **only from Settings** (kept in the local SQLite file); keys in the system environment are ignored, and `backend/.env` holds only the data-provider keys (D10). The catalogue lives in `backend/model_catalogue.json` (prices as of 2026-09-26): OpenAI `gpt-6-luna`, `gpt-5.4-mini`, `gpt-6-sol`, `gpt-6-astra`; Anthropic `claude-haiku-4-5`, `claude-sonnet-5`, `claude-opus-5`. |
| D10 | Research tools | Agent tools are **configured in the backend** and pluggable. v1 uses **Tavily** for web search (free tier: 1,000 credits/month; chosen by `SEARCH_PROVIDER`, D34) and Finnhub (D7) for market data. Data-provider keys (`FINNHUB_API_KEY`, `TAVILY_API_KEY`, optional `TIINGO_API_KEY`) go in `backend/.env`, and only the chosen provider's key is required (D38). LLM keys are entered on the Settings page (D9). |
| D11 | Anomaly warning | The Research Agent flags an **unusual price jump (roughly 8%+ in a day) with no matching news** as a warning in the decision log. Volume is not available on Finnhub's free tier, so v1 checks price only. Full scam detection and social signals stay parked. |
| D12 | Agent roles | **Trading Agent:** owns the portfolio and makes the final buy/sell/hold call. **Research Agent:** called by the Trading Agent as needed; uses the web search and market data tools and reports findings with sources, anomaly warnings and market context (D40). |
| D13 | Run limits | Per decision run: at most **3 Research Agent calls** and **5 web searches**, enforced in code. Market data calls are not capped beyond the provider's own rate limit. |
| D14 | Refresh limits | A "Refresh watchlist" run may use up to **20 web searches**. Flow: broad market scan with a few searches → shortlist using free market data → deeper checks on the top candidates → final 10–20 tickers, each with a reason. There is no separate cap on Research Agent calls during a refresh; the 20-search limit bounds it. |
| D15 | Storage | A single local **SQLite** database file holds the portfolio, trades, watchlist, decision logs, settings (including LLM keys, D9), value history (D33) and cached price history (D36). A run and its resulting portfolio are saved in **one transaction** (D19). The file is `backend/data/trade_simulator.sqlite3` (git-ignored; delete it to start fresh). |
| D16 | UI | **FastAPI** backend (REST API) plus a separate **React** (Vite + TypeScript) frontend. The server listens on **127.0.0.1 only**, because it holds API keys and has no login. `trade-sim serve` serves the API and the built UI at `http://127.0.0.1:8000`. "Run now" and "Refresh watchlist" start in the background; the UI polls for status and shows results when done. Screens: tabs **Home, Decision log, Watchlist** (D32) and a **Settings** page behind a gear icon (D29). Market times are shown in the exchange's timezone. |

## Engineering principles

| ID | Topic | Decision |
|----|-------|----------|
| D17 | Clean Code + Clean Architecture | Follow Uncle Bob's principles, kept lightweight with **three layers**, one folder each under `backend/src/trade_simulator/`: **core** in `core/` (portfolio, trading rules, run limits; no framework or external imports), **use cases** in `application/` (refresh watchlist, run decision, execute trade; the interfaces adapters implement are in `application/ports.py`), and **adapters** in `adapters/` (FastAPI, SQLite, OpenAI Agents SDK, Finnhub, Tavily, Tiingo; wired together in `adapters/bootstrap.py`). Dependencies point inward only. |
| D18 | TDD | Write tests first for the core and use cases. Agent and tool wiring is tested with **fake AI and tool responses**. External APIs are mocked in unit tests, with a few opt-in integration tests. How good the AI's decisions are is judged from the decision logs and P&L, not unit tests. |
| D19 | Error handling | Trades are **atomic**: saved fully or not at all. Failed runs are recorded in the decision log as "Failed: reason". External calls use typed exceptions and limited retries. Full tracebacks go to a log file, not the UI. **API keys are never logged.** |
| D39 | Roadmap after v1 | 1) **Run v1 for a few trading days** to validate the agents, rules and real costs. 2) **Multiple trading agents** competing, each with its own portfolio, model and history (a big structural change). 3) **Agent-written strategies** per agent, revisable in periodic reviews (a medium change built on step 2). Each is designed with the user one decision at a time before building. |
| D38 | Swappable external tools | **Every external tool sits behind an interface our app owns**, with one adapter per provider, **chosen by config** (only the chosen provider's key is required), **never named in the UI**, and tested with fakes. Applies to market data, web search (D34), price history (D36) and any future tool. |

## Architecture

| ID | Topic | Decision |
|----|-------|----------|
| D20 | Run flow | **The agent proposes, the code checks, and trades execute automatically.** The Trading Agent returns proposed orders with reasoning. It never touches the portfolio directly. The core validates each order against D6 (cash, 20% cap, whole shares, fees, no shorting). Valid orders execute immediately with no human approval, at the prices fetched at the start of the run; rejected orders are logged with the reason. A run is a **short burst** (about 30 seconds to 2 minutes; a refresh takes about 2 to 5 minutes), the same in every run mode. **Runs never overlap:** a scheduled run due while another is in progress is skipped, and "Run now" is disabled until the current run finishes. |
| D21 | Market closed | While the US market is closed (nights, weekends, holidays), **"Run now" is disabled** and shows when the market next opens. Scheduled modes only run during market hours. **"Refresh watchlist" is available at any time.** Open/closed status comes from the exchange calendar, including holidays and early closes. |
| D22 | Decision log entry | Each run records: **time and trigger** (Manual / Daily / 15-min / Refresh); **status** (Completed / Failed with reason / Skipped); **research findings** per stock with source links and anomaly warnings; **proposed orders** with the agent's reason; **result per order** (Executed at price + fee, or Rejected + reason); and the **run cost** (AI tokens and web searches used). The run cost also records the model used, so the UI shows an **estimated dollar cost** from the model catalogue. The Trading Agent's overall reasoning is stored as an "OVERALL" finding (so a "hold" run still explains itself); a refresh stores a "MARKET" overview. |
| D23 | Benchmark | The portfolio view shows the portfolio's return **next to the exchange's benchmark index over the same period**, as if the starting capital had been put into that index on day one. For the US the benchmark is the **S&P 500 (via SPY)**. Tracking starts the first time the portfolio is viewed with a SPY price available; that price and time are stored. |
| D24 | Exchange profile | Everything exchange-specific lives in one **exchange profile**: the stock pool (D4), trading hours, timezone and holiday calendar (D21; US uses the official `XNYS` calendar via the `exchange-calendars` library), currency, starting capital (D5), broker fee (D6), and benchmark (D23). **Nothing exchange-specific is hard-coded.** v1 ships only the **US profile**; Tokyo and India are added later as new profiles. |
| D25 | Agent visibility | **Prompts live in their own files** (e.g. `prompts/trading_agent.md`), separate from code, so they are easy to review and edit. **Every run is traced** with the OpenAI Agents SDK's built-in tracing, viewed in the **OpenAI dashboard** (Traces). Each decision log entry stores its trace ID and shows a **"View trace"** link. Traces need an OpenAI key: if one is present, runs are traced **even when using Anthropic models**; with only an Anthropic key, runs are not traced, but the decision log still records findings, orders and reasons. |
| D26 | Build order | **All six steps are done** (see Changelog). 1) **Core rules** (portfolio, trading rules, fees, 20% cap, exchange profile; tests first, no AI) → 2) **Storage** (SQLite, atomic trades) → 3) **Market data** (Finnhub prices, market hours) → 4) **Agents** (Trading + Research, prompt files, Tavily, run limits, tracing, decision log) → 5) **API + UI** (FastAPI + React) → 6) **Scheduler** (Daily and 15-min modes). Each step ends with something that works and is tested. |
| D27 | MCP-ready agents | Agents use built-in tools today. **MCP servers can be added later without code changes** by listing them in `backend/mcp_servers.json` (stdio or HTTP), choosing which agents get each one (`research`, `trading`), with secrets referenced as `${ENV_VAR}`. No file means no MCP servers. Only trusted, vendor-official servers should be added. MCP tool calls are not counted against the web search limits (D13, D14). |
| D28 | Live agent activity | While a run is in progress, the UI shows **what the agents are doing, live, as a step timeline**: one line per step (agent started, Research Agent asked, each tool call with its input such as symbols or search query, short results, proposed orders, and the rules check result). Built in our app from the SDK's step notifications, independent of the OpenAI dashboard tracing (D25). **Live only:** the timeline is held in memory while the run is in progress and is not saved; afterwards the decision log (D22) and the OpenAI dashboard trace remain. **Placement:** the in-progress run appears as the **first entry in the Decision log**, its timeline growing live; when the run finishes it becomes the normal run summary in the same place. |
| D40 | Market context in research | Research covers **market-wide events** (economy, central banks, politics, geopolitics, regulation), not only company news. **New free tool `get_market_news`:** general market headlines from the market data provider (Finnhub's free `general` news; checked 2026-09-27: 100 headlines over about 3 days), capped at the **25 newest**, with summaries trimmed, behind the market data interface (D38). No web searches used. **Research Agent:** in each run, first scan market news for the events that matter, then for every stock it reports on say whether and how it is exposed to them (sector, supply chain, regulation, where it sells), with sources; it may spend its normal web searches following up a major event (limits unchanged, D13, D14). Market context is stored as a **"MARKET" finding** (as a refresh already does, D22) and appears with the research in the Decision log (D31); no new screens. **Trading Agent:** its input includes the **latest watchlist refresh overview** with its date; its first research request asks for market context; it weighs market-wide risks alongside company news. The watchlist refresh's market scan uses the tool first, before web searches. |

## What the user sees
Summary only; the layouts are in the UI design section below.
- **Home** (D32): total value, the agent's return and the S&P 500's over the same period, a value chart against the S&P 500, the agent's latest decision, holdings and cash
- **Decision log** (D31): one expandable row per run, newest first, with the live run on top (D28)
- **Watchlist** (D30, D37): one row per stock with a trend line, an expandable price chart, and a "Refresh watchlist" button
- **Settings** (D29, D35), behind the gear icon: OpenAI and/or Anthropic API keys, the model for all agents (with prices), and the run mode
- **"Run now"**: disabled while the market is closed, showing when it next opens (D21)

## UI design (agreed step by step with previews; built as agreed)

| ID | Topic | Decision |
|----|-------|----------|
| D29 | Settings entry point | Settings is **not a tab**. A **gear icon in the top-right corner** opens a separate Settings page holding all configuration: **API keys** (OpenAI, Anthropic: masked key, Save, Remove), **Model for all agents** (table of models for providers with a key, with input/output prices, one selected), and **Run mode** (D35). |
| D30 | Watchlist layout | The Watchlist tab stays, shown as a **table with one row per stock**: symbol, current price, today's change, whether it's held, and the agent's reason (with its sources). |
| D31 | Decision log layout | One row per run, **newest first**; a live run sits on top with its step timeline (D28). Each row's header gives the one-line answer: time, trigger (Run now / Daily / Every 15 min / Watchlist refresh), status, trades executed and rejected, warnings, duration. **Clicking a row opens it**, reading top to bottom: 1) decision summary in the agent's words, 2) orders with the rules result for each (executed at price + fee, or rejected + reason), 3) research findings with sources and warnings, 4) cost (model, tokens, searches, estimated $, trace link). The newest run is open by default. |
| D32 | Home screen | Alpha Arena style (the agent is the centre). Tabs: **Home, Decision log, Watchlist** (Settings via the gear icon, D29). Home shows, top to bottom: three numbers (total value, the agent's return, the S&P 500 over the same period); a **value-over-time chart of the portfolio against the S&P 500**; the **agent's latest decision** in its own words with its trades and warnings, linking to the Decision log; and compact **holdings** with cash. |
| D33 | Value history | To draw the chart, the app **records portfolio value and the benchmark (SPY) price after every run and once per trading day at the close**. The daily close snapshot is taken by the scheduler (step 6) while the app is running. |
| D34 | Search provider is invisible and swappable | The UI never names the web search provider: it talks about **"web searches"** and a **"free monthly allowance"**. The provider (Tavily today; Playwright or another later) is a swappable adapter behind a neutral search interface, and it **declares its own pricing** (free searches per month, price per extra search), which cost estimates use. Its API key is required only when that provider is the one in use. |
| D35 | Run mode section (Settings) | A **Run mode** section on the Settings page (below the model): three cards (**Manual**, **Daily**, **Every 15 min**), one selected. Each card says when runs happen and shows **(a) the estimated AI cost in $** for the chosen model (per run for Manual, per month for Daily and 15-min), and **(b) whether its web searches fit the free monthly allowance**; if not, when it runs out, and that research then continues without web search until the month resets. No made-up search charges. Below the cards: **"Next scheduled run"** in exchange time (hidden in Manual). AI cost estimates use the **average tokens of your past decision runs**; with fewer than 3 such runs, a starting guess (~20k tokens in / 2k out, 5 searches per run) labelled "rough estimate". |
| D36 | Price history source | Daily price history for stock charts comes from **Tiingo's free plan** (1,000 requests/day, 50/hour, 500 stocks/month, 30+ years; personal/internal use), called directly by the app through a swappable **price-history adapter**. History is cached in SQLite and topped up once a day, so a stock costs one request per day at most. Needs a free `TIINGO_API_KEY` in `.env`; **without it the app still starts and the charts show as not set up**. Finnhub's free plan has no price history (checked: 403). History is topped up in the background (at start-up, after runs, when the Watchlist is opened), so pages never wait on the provider, and the provider's hourly limit is respected. **Abstraction:** the app owns a `PriceHistorySource` interface (daily bars for a symbol since a date, plus declared request limits); Tiingo is one adapter, chosen by `PRICE_HISTORY_PROVIDER` (default `tiingo`); the UI never names the provider. **Schema:** `price_history` (`exchange`, `symbol`, `day`, `open`, `high`, `low`, `close`, `adj_close`, `volume`, `source`; key `exchange`+`symbol`+`day`; money stored as exact decimals; charts use `adj_close` so splits don't distort them) and `price_history_sync` (`exchange`, `symbol`, `first_day`, `last_day`, `last_checked_at`) to avoid wasted requests on weekends and holidays. Trade markers come from existing executed orders; no new table. |
| D37 | Watchlist charts | Each Watchlist row gets a small **"Last month" trend line** (green if up over the month, red if down). **Clicking a row opens its price chart** below it (one open at a time): daily adjusted closing price with **1M / 3M / 1Y** buttons, the period's low and high, and **markers where the agent bought (green) or sold (red)**, with quantities. Data comes from the cached price history (D36). |

- Tokyo and India exchanges
- Scam / pump-and-dump detection
- Social media and market-conversation signals

- Agent-specific models (e.g. a cheaper model for research, a stronger one for trading); v1 uses one model for all agents (D9)
